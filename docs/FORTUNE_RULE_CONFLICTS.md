## 冲突 1："卦命诀"等争议规则（八字映射本命卦）

```
规则：是否根据八字（出生年月日时）直接换算出一个人的"本命卦"。
来源 A：部分后世命理书（托名"卦命诀"等），以出生年干支 + 性别起卦，得到"你本命卦是 XX"。
来源 B：京房八宫原典（《京氏易传》）里并没有"按八字定本命卦"的说法；八宫是占卦用的卦变体系。
冲突：
  - A 派：八字 → 本命卦，是个人终身卦。
  - B 派：八宫是占卦工具，不是给人"配"卦的。
项目当前选择：
  - 不根据八字凭空映射本命卦。
  - 提供三种来源方式，让用户自己选：
    1. 用这次起卦的卦作为当前卦（默认）。
    2. 用户自己指定一个卦作为"本命/研究卦"。
    3. 用户用出生年月日按"卦命诀"算法生成一个候选，但 UI 上明确标注"此算法为后世说法，非京房原典，仅供参考"。
原因：
  - 项目立场是"研究层不替用户下结论"。
  - 既然流派分歧大，就不把某一派当成项目默认真理。
版本：FORTUNE_RULESET_VERSION 1.0.0
```

## 冲突 2：大运顺逆的性别约定

```
规则：大运干支从月柱起，顺排还是逆排？
来源 A：阳男阴女顺排，阴男阳女逆排（主流子平法）。
  - 即：年干为阳 + 男 → 顺；年干为阴 + 女 → 顺。
来源 B：部分流派按"阳男阴女顺、阴男阳女逆"但 genderCode 约定相反（有软件把 male 传 0、female 传 1）。
冲突：
  - 同一个八字，genderCode 传反，整步大运方向就反。
项目当前选择：
  - 跟 lunar-javascript（当前 ^1.6.13）的约定走：male → 1，female → 0。
  - traditionalGenderParam: 'male' | 'female' | 'unspecified'。
  - unspecified 不猜性别、不算大运。
原因：
  - 依赖库已经固定，不自己另造一套 genderCode 约定，避免和库对不上。
  - 见 FORTUNE_ENGINE.md 第五节。
版本：FORTUNE_RULESET_VERSION 1.0.0
```

## 冲突 3：起运年龄计算（三天 vs 其他）

```
规则：从出生日到最近的节气，几天折合成几岁起运？
来源 A：主流"三天折一岁"（一天折四个月）。
来源 B：部分流派用"一天折一岁"或按节气精确到时辰折算。
冲突：
  - 同一个八字，A 算出 3 岁起运，B 算出 7 岁起运。
项目当前选择：
  - 直接用 lunar-javascript 的 `yun.getStartYear()` / `yun.getStartAge()` 结果。
  - UI 上标注"起运年龄为虚岁，按三天折一岁折算"。
  - 不自己另写一套折算。
原因：
  - lunar-javascript 内部实现的就是主流三天折一岁法。
  - 项目不重新发明轮子，也不引入第二种算法并列。
版本：FORTUNE_RULESET_VERSION 1.0.0
```

## 冲突 4：十六变阶段名称（外戒/内戒的位置和名称）

```
规则：游魂之后、归魂之前的两个阶段叫什么？
来源 A：《易隐》通行本：游魂 → 外戒 → 内戒 → 归魂。
来源 B：部分后世抄本/改编本：游魂 → 归魂 → 外戒 → 内戒，或把这两个阶段叫"斋戒""持戒"。
冲突：
  - 阶段顺序不同，按 FLIP_SEQUENCE 翻出来的卦也会对应到不同的阶段名。
项目当前选择：
  - 采用《易隐》通行本顺序：本宫 → 一世~五世 → 游魂 → 外戒 → 内戒 → 归魂 → 绝命 → 血脉 → 肌肉 → 骸骨 → 棺椁 → 冢墓。
  - FLIP_SEQUENCE = [1,2,3,4,5,4,3,2,1,2,3,4,5,4,3,2] 对应这个顺序。
  - 乾宫 golden sequence 锁定：乾 姤 遁 否 观 剥 晋 旅 鼎 大有 离 噬嗑 颐 益 无妄 同人 乾。
原因：
  - 见 JINGFANG_16_SOURCE_NOTES.md 第五节。
  - 项目不支持其他抄本顺序；用户若想看其他版本，视为不同 ruleset，不混在 1.0.0 里。
版本：FORTUNE_RULESET_VERSION 1.0.0
```

## 冲突 5：《易隐》身命三限的起限方法

```
规则：《易隐》身命三限（初限 / 中限 / 末限）怎么起？
来源 A：按卦数 + 动爻起限，每限若干年。
来源 B：按纳甲干支起限。
来源 C：按八卦方位起限。
冲突：
  - 三种方法算出的"初限起止年龄"完全不同。
  - 《易隐》原文本身传本众多，起限口径不统一。
项目当前选择：
  - v1 不实现具体起限算法。
  - 类型占位在 types.ts，UI 上只显示说明文字：
    "《易隐》身命三限起限方法流派分歧，本版本暂不展示具体推算。"
  - v2 如果要做，必须先在本文件记录选定的一派和来源。
原因：
  - 贸然选一派会误导用户，不如不做。
  - 见 FORTUNE_ENGINE.md 第七节。
版本：FORTUNE_RULESET_VERSION 1.0.0（未实现）
```

## 冲突 6：时柱划分（子初换日 vs 午夜换日）

```
规则：晚 23:00 到 24:00 这一个时辰，算今天的子时还是明天的子时？
来源 A：子初换日（传统说法）——23:00 就算第二天的早子时。
来源 B：午夜换日（现代公历）——00:00 才算第二天。
冲突：
  - 23:30 出生的人，两种算法日柱差一天，整个八字都不同。
项目当前选择：
  - 复用问卦引擎已有的 DayBoundaryRule（见 RULES.md）：
    - 'midnight'（默认）：00:00 换日。
    - 'zi_hour'：23:00 子初换日。
  - 出生档案里继承同一个设置，不另造一套。
  - UI 上明确显示当前用的是哪一种。
原因：
  - 项目已经在问卦引擎里处理过这个分歧，运势模块直接复用，不另立标准。
版本：FORTUNE_RULESET_VERSION 1.0.0（复用 RULESET_VERSION 的 DayBoundaryRule）
```

## 冲突 7：本命卦来源（京房原典 vs 后世扩展）

```
规则："本命卦"这个说法本身有没有原典依据？
来源 A：京房《京氏易传》只讲八宫卦变，没有"人有本命卦"的说法。
来源 B：后世（包括部分现代通俗读物）把八宫/十六变对应到个人，衍生出"本命卦""终身卦"。
冲突：
  - "本命卦"是后世概念，不是京房原典。
项目当前选择：
  - 在 UI 上把"本命卦"改叫"研究卦"或"当前卦"，避免暗示"你天生就是这一卦"。
  - 如果用户坚持要看"本命卦"，走冲突 1 的第三种方式：自己选卦 / 按卦命诀生成候选，并标注"后世说法"。
  - 十六变模块只对"当前卦"做结构研究，不宣称"这是你天生的卦"。
原因：
  - 不把后世附会写成原典。
  - 见 JINGFANG_16_SOURCE_NOTES.md 第二节。
版本：FORTUNE_RULESET_VERSION 1.0.0
```

## 冲突 8：十六变是否按年龄平均

```
规则：十六变 17 个阶段是否对应 0-80 岁、每卦 5 年？
来源 A：部分现代通俗讲解（包括南怀瑾相关讲解）把十六变类比为人生阶段，给出大致年龄区间。
来源 B：京房原典里十六变是卦变结构，不对应年龄。
冲突：
  - A 派给了年龄表，B 派说没有这个对应。
项目当前选择：
  - 不按年龄平均。
  - 源码常量 NO_AGE_MAPPING_NOTE 明确说明。
  - 现代类比资料只作为 modern-analogy 来源层，研究模式可折叠展示，长辈模式不展示。
原因：
  - 见 JINGFANG_16_SOURCE_NOTES.md 第九节。
版本：FORTUNE_RULESET_VERSION 1.0.0
```
